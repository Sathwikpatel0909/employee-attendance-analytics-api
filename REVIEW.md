# Starter code review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Mongo configuration | The original defaults embedded `mongodb://localhost:27017` and `attendance_db`, and did not create the required indexes. | Start with an injected `MONGO_URI` / `MONGO_DB`; requests otherwise use hard-coded defaults and duplicate races remain possible. | Read process environment before fallback defaults and added idempotent named indexes at startup. Existing process variables win over `.env` (`load_dotenv(override=False)`). |
| 2 | `health` | Always returned 200 without checking MongoDB readiness. | Stop MongoDB and GET `/health`; starter still says `ok`. | Ping MongoDB and return 503 on connection errors. |
| 3 | `EmployeeIn` | Accepted malformed employee codes, email, names, departments, dates, and shift strings; did not reject equal shift times or ignore derived/extra fields explicitly. | Submit `emp_code="x"`, an invalid date, `shift_start="25:00"`, or identical shift endpoints; starter accepts them or errors later. | Added contract patterns, length checks, real calendar-date validation, unequal shift validation, and ignored extra request fields. |
| 4 | `create_employee` | Check-then-insert was race-prone; there was no unique index. `created_at` was naive and returned as an ISO datetime instead of epoch milliseconds. | Send concurrent creates for one code or inspect `created_at`; more than one create could succeed and timestamp has wrong representation. | Unique `emp_code` index makes the insert atomic for duplicates; catch duplicate key as 409; store UTC BSON datetime and serialize epoch milliseconds. |
| 5 | `list_employees` | `skip = page * page_size` skipped the first page; count ignored department; results were unsorted and pagination had no bounds. | Page 1 omits the first 20; filtered total disagrees with items; page_size >100 is accepted. | Count the filtered query, sort by `emp_code`, use `(page-1)*page_size`, and validate page/page_size. |
| 6 | `compute_late_minutes` | Compared naive/local timestamps with wall-clock shift values, mishandled overnight shifts, and did not truncate instants first. | With 09:30 shift, compare exact 09:40:01 and overnight punches; host timezone changes results and subsecond values leak into calculations. | Convert instants to IST, calculate from the local shift date, apply strict 10-minute grace, and store truncated instants. |
| 7 | `compute_work_hours` | Python `round` uses half-even behavior for ties rather than required decimal half-up rounding. | A duration whose hours tie at a hundredth boundary can round differently. | Use `Decimal` and `ROUND_HALF_UP` on whole-second duration. |
| 8 | `compute_overtime` | Used the record start date's shift-end unconditionally, omitted next-day end for overnight shifts, and returned any positive minutes rather than requiring 30. | Overnight 22:00–06:00 or a punch-out 29 minutes after shift end yields incorrect overtime. | Compute the end on the next day for overnight schedules and return floor minutes only at 30 or more. |
| 9 | `punch_in` | Missing employees caused a 500; falsy timestamp `0` silently became now; seconds/local timezone were used; status and epoch ranges were unchecked; attendance date ignored IST and overnight ownership. | Unknown employee; `punched_at=0`; float/string/seconds values; UTC date boundary; 01:00 punch into 22:00–06:00 shift. | Validate strict epoch milliseconds and presence status, return 404 for unknown employees, use UTC/IST conversion and overnight date rule, and truncate before storage. |
| 10 | `punch_in` duplicate handling | A find-before-insert check did not prevent simultaneous duplicate attendance rows, and successful response included forbidden `id`. | Parallel same-employee/same-day requests can both pass the check; response leaks Mongo identity. | Enforce unique (`emp_code`,`date`) at database level and map duplicate key to 409; serialize only contract fields. |
| 11 | `list_attendance` | Read every matching document, sorted and paginated in Python; this is unbounded at 100k. Ordering omitted `emp_code` tie-break; total was materialized count, invalid ranges/status/dates were not rejected, and `_id`-derived `id` leaked. | Large collection causes memory/latency growth; same-day records vary order; reverse date range or invalid status is accepted. | Count the applied query separately; validate dates/status/page inputs; sort and paginate in MongoDB; project out `_id`; return contract response with legacy defaults. |

## Checked and found consistent

- `IST` was declared with the correct UTC+05:30 offset; the defects were in how the helpers used it.
- Default pagination values (page 1, page size 20) and punch-in default status `PRESENT` matched the contract; the starter lacked bounds and validation.
- The initial attendance record's intended defaults (`punch_out` and `work_hours` null, overtime 0, half-day false, empty history) were correct and are preserved.
- Attendance filters were intended to be exact matches and date bounds inclusive; the repaired query retains those semantics.

The defects above describe the original starter implementation and the repairs made across Stages 1–4. The repaired implementation also includes punch-out, regularization, four analytics routes, and the explain route. The analytics and explain pipelines have been exercised with test doubles, but their results and execution plans have not been verified against a live MongoDB server. The explain contract documents 404 for a missing referenced employee or department and 503 when MongoDB cannot execute explain, in addition to 422 validation errors.
